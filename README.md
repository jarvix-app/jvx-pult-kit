# jvx-pult-kit — рабочее место агентов

Набор, который клонируют на каждую машину человека из команды. Он объясняет агенту любой модели, кто он по роли,
как ходить в систему [jvx-pult](https://github.com/jarvix-app/jvx-pult) и что можно и нельзя. А на компьютере
продакта ещё и запускает адъютанта по расписанию.

Подписку Claude система не трогает: человек подключает свой Claude Code сам, сервер его учётных данных Anthropic
не видит и не хранит. Адъютант работает на подписке продакта, в его Claude Code, на его компьютере.

## Что здесь лежит

| Путь | Для кого и зачем |
|---|---|
| `AGENTS.md` | общие правила для агентов любой модели: определить роль, запреты, коды выхода |
| `CLAUDE.md` | Claude Code: подключает `AGENTS.md` и добавляет то, что относится только к нему |
| `roles/member-agent.md` | агент разработчика или тестировщика (роль `member`) |
| `.pult-role.md`, `.claude/commands/` | **роль адъютанта (роли `adjutant` и `product`) и его команды `/utro`, `/den`, `/vecher`, `/nedelya`, `/mesyac`, `/razbor`, `/raund`, `/cikl`, `/sprint`, `/plan`, `/obhod`. В git набора их нет: их отдаёт сервер только продакту и адъютанту, а `pult kit pull` (его зовёт установщик и сторож) пишет сюда. Сотрудник и его агент директив адъютанта не получают** |
| `.claude/settings.json` | разрешения для запусков без человека: только `pult`, сеть закрыта |
| `scheduler/` | сторож без LLM и скрипты расписания Windows |
| `scripts/install.mjs` | ставит файл роли по роли токена: роль сотрудника берёт из набора, роль и команды адъютанта тянет с сервера (`pult kit pull`) |
| `voice/` | голос: отдельная часть, пишется отдельно и этим набором ролей не затрагивается |

Имена команд латиницей намеренно: `/utro` — утро, `/den` — день, `/vecher` — вечер (слой дня пульса), `/nedelya` — неделя
(день недели из настроек, слой недели), `/mesyac` — месяц (последний рабочий день, слой месяца), `/razbor` — разбор входящих,
`/raund` — раунд вопросов продакту, `/cikl` — ритуалы циклов проектов (планирование, сдача, ретроспектива), `/sprint` — личный
спринт человека, `/plan` — расспрос продакта по одному проекту и раскладка ответов по эпикам, вехам и техдолгу (запускает только человек,
сторож её не трогает), `/obhod` — недельный обход проектов с продактом: по одному проекту за раз, решения записываются существующими
командами, «посмотрел» адъютант ставит только по слову продакта (запускает только человек, сторож её не трогает). Отдельного расписания у них нет: что пора, говорит сервер (`pult cycle due`), а спрашивает его обычный запуск `/utro`.
Документация Claude Code не говорит, принимаются ли кириллические имена
файлов команд, а сторож будит адъютанта именно по имени команды. Имена команд задаёт сервер (`resources/kit/adjutant/commands`),
поэтому менять их здесь бесполезно: следующая перетяжка вернёт серверные.

## Что набор умеет по возможностям сервера

- **Вопросы продакту.** Агент сотрудника не гадает на сомнительном месте задания: `pult ask` (ситуация, 2–4 варианта, вариант по
  умолчанию, срок), `pult questions`, `pult question withdraw`. Ответ даёт только продакт, кнопкой в Telegram или в вебе; он виден в
  `pult show` и `pult my`. Не ответил к сроку — сервер сам идёт по варианту по умолчанию. Адъютант за продакта не отвечает, а напоминает
  (`/utro`, `/nedelya`, `/razbor`).
- **Ожидания («ждём чужих»).** Договоры, доступы, аккаунты, песочницы: `pult wait add|list|show|edit|asked|nudge|got|note|drop|link|unlink|due|templates|checklist`.
  Сигналы по срокам считает сервер (`pult wait due`), адъютант разбирает их в `/utro` и `/nedelya`; при заведении проекта спрашивает продакта
  по типовому перечню (`/plan`). Заказчику сервер не пишет: готовый текст лежит в `pult wait show`, его пересылает человек. Агент сотрудника
  говорит человеку, что задача «ждёт W-…», и отмечает `asked|nudge|got` только со слов человека.
- **Состояние проекта и обход.** Сервер считает по каждому проекту светофор с причинами (число и код у каждой), блок «ждёт тебя», срок:
  `pult project health <код>`, очередь `pult review`, отметка `pult project reviewed <код>` (пороги — `pult settings --section health`).
  Вывод по проекту (четыре строки) адъютант пишет в `/nedelya` недельным слоем с охватом проекта: он виден на странице проекта под светофором.
  Обход ведёт человек командой `/obhod`; `/utro` одной строкой называет красные и давно не смотренные проекты. Люди проекта — приватное.
- **Факты про срок в пульсе.** В `pult context` и `pult digest show` есть «не взято» (открытые задачи без брони дольше порога) и «сроки проектов»
  (дней до срока, готовность вехи сдачи, проект без срока назван прямо): адъютант выносит их в `/utro` и `/nedelya`.
- **Качество сдачи.** У задачи есть сценарии проверки (`pult task scenario add|edit|retire`): их записывают при постановке и по ним идёт
  ручная проверка перед сдачей. При сдаче агент передаёт заявку «проверено на стенде» (`pult done … --stand-url --stand-scenarios`), а
  **подтверждает её только сам человек**: кнопкой «Проверил сам» в Telegram или на странице задачи. Агент и адъютант подтвердить не могут,
  команды нет. Баг, выросший из сданной задачи, заводят с `--grew-from`; причину предлагает адъютант по фактам (`pult cause show|propose`),
  утверждает только продакт (`pult cause approve|reset`), человек бага может один раз возразить в вебе. Недельные факты по людям и проектам —
  `pult quality facts`: только продакту, в группу и в ретро ничего по людям не уходит (`/nedelya`).
- **Карта тестирования.** Зоны → разделы → сценарии проверки продукта: `pult testmap show|import|scenario add`, `pult task sections`
  (какие разделы задела задача, от этого считается «перепроверить»). Карту грузит адъютант с `--dry-run` и по слову продакта; проходят её
  тестировщики руками в вебе, отметок прохода у агентов нет. Свод по картам адъютант даёт в `/utro` и `/mesyac`.

## Установка на машину человека

Нужны Node.js 20 или новее и Claude Code (или другой агент, умеющий читать `AGENTS.md`). Пути ниже примерные.

1. Клонировать репозиторий набора. Репозиторий сервера `jarvix-app/jvx-pult` **закрытый**, и доступ к нему **не нужен**: утилиту `pult`
   раздаёт сам сервер команды, а набор адъютанта сервер отдаёт только продакту и адъютанту.

   ```powershell
   cd D:\Work; git clone https://github.com/jarvix-app/jvx-pult-kit.git
   ```

2. Поставить утилиту `pult` по адресу пакета на сервере команды (адрес тот же, что у команды в шаге 3):

   ```powershell
   cd D:\Work; npm.cmd install -g https://<адрес команды>/cli/pult.tgz
   ```

   Обновляется утилита той же командой. `pult --version` и `pult whoami` сами сверяют версию с сервером и одной строкой
   подсказывают обновление, если пакет на сервере новее. Если пакет не собран, сервер отвечает 404 с пояснением: скажите продакту.

3. Привязать машину. **Токен каждый выдаёт себе сам**: войдите в веб команды (через Jarvix ID или по ссылке бота `/web`),
   откройте «Машины» → «Выдать токен», роль «сотрудник». Экран выдаёт токен только тому, кто вошёл, поэтому продакт
   выдать его за вас не может: токен, выданный продактом на своём экране, будет токеном ПРОДАКТА (или его адъютанта)
   со всеми управленческими правами — на чужую машину его ставить нельзя. Запасной путь без входа в веб — оператор
   сервера (`php artisan pult:token:issue <команда> "<ваше имя>" "<машина>" --role=member`). Токен показывается один раз;
   в переписку его не вставляйте. Адрес команды (вида `https://<команда>.<домен>`) у каждой команды свой,
   его называет продакт. Через stdin токен не виден в списке процессов:

   ```powershell
   "ТОКЕН" | pult login - --server https://<адрес команды>
   ```

4. Проверить, что система видит вас и вашу роль:

   ```powershell
   pult whoami
   ```

   В ответе должны быть **ваше имя** и роль `member`. Чужое имя или роль `adjutant` / `product` — стоп: токен не ваш,
   дальше не ставьте ничего и скажите продакту, чтобы он его отозвал.

5. Поставить файл роли в каталог вашего проекта (`member` получит только инструкции агента сотрудника):

   ```powershell
   cd D:\Work\jvx-pult-kit; node scripts\install.mjs --target D:\Work\мой-проект
   ```

   Сначала можно посмотреть, что будет записано: добавьте `--dry-run`.

   **Если у проекта уже есть свой `CLAUDE.md` или `AGENTS.md`**, установщик их не трогает никогда, и с `--force` тоже.
   Правила Пульта ложатся рядом в `.pult-rules.md`, а подключает их блок в `CLAUDE.local.md` (Claude Code читает его
   вместе с `CLAUDE.md` проекта; свой текст в этом файле сохраняется). Три файла набора (`.pult-role.md`,
   `.pult-rules.md`, `CLAUDE.local.md`) дописываются в `.git/info/exclude` проекта и в его репозиторий не попадают.
   Агенту, который читает только `AGENTS.md`, на `.pult-rules.md` надо указать самому.

6. По желанию подключить MCP к Claude Code (те же операции инструментами `pult_*`):

   ```powershell
   claude mcp add --scope user pult -- pult-mcp
   ```

Один человек — несколько машин: шаги 3-5 повторяются на каждой, у каждой машины свой токен.

## Установка на компьютер продакта

То же, что выше, но с токеном роли `adjutant` (токен продакта с флагом адъютанта), и дополнительно расписание.
Адъютант работает в каталоге самого набора: настройки лежат здесь, а роль (`.pult-role.md`) и команды `/…` (`.claude/commands/`)
сюда пишет `pult kit pull` с сервера. Ни то, ни другое в git набора не входит.

1. Шаги 1-4 выше. В ответе `pult whoami` должна быть роль `adjutant`.

2. Один раз войти в Claude Code под своей подпиской и убедиться, что он работает из каталога набора:

   ```powershell
   cd D:\Work\jvx-pult-kit; claude
   ```

3. Поставить роль и команды адъютанта в сам набор (установщик зовёт `pult kit pull`; нужен токен продакта или адъютанта и утилита,
   в которой есть команда `pult kit pull`, см. шаг 2):

   ```powershell
   cd D:\Work\jvx-pult-kit; node scripts\install.mjs
   ```

   То же вручную: `pult kit pull --dir D:\Work\jvx-pult-kit`; хеш набора на сервере — `pult kit hash`. Сторож сам сверяет хеш перед
   каждым запуском адъютанта и перетягивает набор, когда роль на сервере сменилась (подробности ниже).

4. Посмотреть план расписания, ничего не меняя:

   ```powershell
   cd D:\Work\jvx-pult-kit; powershell.exe -NoProfile -ExecutionPolicy Bypass -File scheduler\install-windows.ps1 -WhatIf
   ```

5. Поставить расписание:

   ```powershell
   cd D:\Work\jvx-pult-kit; powershell.exe -NoProfile -ExecutionPolicy Bypass -File scheduler\install-windows.ps1
   ```

   Будут созданы задания Планировщика: сторож (интервал берётся из настроек команды, по умолчанию 5 минут; плановые
   `/utro`, `/den`, `/vecher`, `/nedelya`, `/mesyac` он запускает сам по часам команды из `pult settings --section adjutant`; `/cikl` и `/sprint` отдельного расписания не имеют, их шаги берёт утренний запуск из `pult cycle due`) и расшифровка голоса каждые 5 минут (`voice/README.md`). Они идут от вашего пользователя и **только пока вы вошли в Windows**: пароль не запрашивается и не
   хранится. Компьютер выключен или спит — запуск не состоится; окно пропущенного планового запуска закрывается
   (в обед утренний запуск не нужен, дневной займёт его место).

6. Проверить вручную один запуск (то же, что сторож сделает в час утреннего запуска; `--force` запускает, даже если сегодня уже было):

   ```powershell
   cd D:\Work\jvx-pult-kit; node scheduler\watchdog.mjs --run utro
   ```

   Состояние и журнал сторожа: `%LOCALAPPDATA%\pult-kit\watchdog\` (`watchdog.log`, `cursor.json`, `stats.json`).

Снять расписание:

```powershell
cd D:\Work\jvx-pult-kit; powershell.exe -NoProfile -ExecutionPolicy Bypass -File scheduler\uninstall-windows.ps1
```

Добавьте `-RemoveState`, чтобы удалить и состояние сторожа. Перед любым из этих вызовов можно добавить `-WhatIf`.

## Как работает сторож

Раз в N минут (интервал сторожа — настройка команды, по умолчанию 5) читает `pult events --since <курсор> --json` и решает по таблице типов событий, требует ли событие
мысли. Будит адъютанта (`claude -p "/razbor"`) только на `inbox.received`, `inbox.transcribed`, `item.submitted`.
Остальные события и неизвестные типы не будят, но считаются (`stats.json`) и пишутся в журнал. События ожиданий и вопросов
(`wait.*`, `question.*`) и качества сдачи (`scenario.*`, `submission.stand_*`, `bug.*`, `testmap.imported`, `testrun.*`,
`item.sections_set`) не будят и неизвестными не считаются: продакта и людей о них уведомляет сам сервер.

- Не чаще одного запуска адъютанта за промежуток из настроек команды (`wake_min_interval_minutes`, по умолчанию 15 минут)
  и не параллельно уже идущему (файл-замок с проверкой, жив ли процесс). Явная переменная
  `PULT_WATCHDOG_MIN_INTERVAL_MS` перекрывает настройку.
- Событие, на которое нельзя разбудить из-за интервала, остаётся ждать: курсор не проходит мимо него.
- Курсор двигается только после успешного запуска или решения не будить. Запись курсора атомарная.
- Нет связи (код 3 у `pult`): тихо ждёт следующего раза. Токен не принят или нет прав (4, 5): громкая запись
  в журнал и в stderr, адъютант не будится.
- Повреждённый файл курсора: понятная ошибка и выход с кодом 2, а не молчаливый пропуск всей истории.
- Перед каждым запуском адъютанта (по событию и плановым) сверяет `pult kit hash` с хешем установленного набора (`kit.json` в
  каталоге состояния) и при расхождении делает `pult kit pull` в каталог набора: сменили роль или команды на сервере, и адъютант
  стартует уже на новых. Нет связи, нет права или перетяжка не удалась: запуск не падает, адъютант стартует на том, что лежит на
  диске, а в журнал идёт строка. Тихие проходы по ленте набор не спрашивают.
- LLM в сторожа не встроен: он только запускает `claude` с фиксированной командой. Текст событий в запуск не идёт.

### Плановые запуски по часам команды

Слои пульса (`/nedelya`, `/mesyac`) идут тем же путём, но не окнами дня: `/nedelya` — в день недели `adjutant.nedelya_day` (по умолчанию
пятница), `/mesyac` — в последний рабочий день месяца (рабочие дни — дни дейлика, их сервер отдаёт в `pult settings`), каждый не раньше
своего часа (`nedelya_at`, `mesyac_at`) и только после сегодняшнего `/vecher`; неделя раньше месяца. Пропущенные слои запуск не
догоняет: адъютант дописывает их при первом запуске (`pult context`, `pult digest missing`).

Часы `/utro`, `/den`, `/vecher` и пояс команды сторож берёт из `pult settings --section adjutant` (кеш в
`rhythm.json`, обновляется раз в 10 минут; сервер недоступен — работает по прошлому кешу, а без него плановых запусков
по часам нет). Окно запуска открывается в его час и закрывается в час следующего, вечернее держится до конца суток.
Сменили часы на экране сервера — Планировщик трогать не нужно, пересчёт идёт на следующей проверке. Единственное, что
остаётся в Планировщике, — сам интервал сторожа: он записан при установке; если его сменили на экране, сторож один раз
предупредит в журнале, и скрипт установки надо запустить ещё раз.

Запуск за день записывается в `scheduled.json` (по дате в поясе команды), и второй за те же сутки не выполняется — ни
сторожем, ни заданием `--run` старой установки. Сбойный запуск тоже считается состоявшимся: он не повторяется каждые
N минут. Плановые запуски идут через тот же замок, что и запуск по событию, поэтому не пересекаются с ним.

## Проверка

```powershell
cd D:\Work\jvx-pult-kit; node --test
```

Тесты идут без зависимостей, с поддельными `pult` и `claude`. Проверки роли адъютанта и его команд (фразы-запреты, имена команд
и флагов `pult …`) живут на сервере, рядом с самими файлами (`cli/test/kit` в репозитории `jvx-pult`). Здесь остаётся сверка общих правил
и роли сотрудника: отдельная проверка сверяет все команды `pult …` из `.md`-файлов набора с таблицей операций настоящей утилиты.
Ей нужен путь к ней:

```powershell
cd D:\Work\jvx-pult-kit; $env:PULT_OPERATIONS_JS = "D:\Work\jvx-pult\cli\src\operations.js"; node --test
```

Вне CI, если рядом лежит клон `jvx-pult`, путь подхватывается сам. В CI этого репозитория проверка пропускается
явно, с сообщением: `jvx-pult` в сборку не подтягивается.
